# color — equivalent mutants

- 139: `value >= 255` → `value > 255` — at exactly 255 the other branch returns `Math.round(255)`, the same 255.
- 155: `linear === undefined` → `true` — disables the `LINEAR_CHANNELS` cache only; the recomputed value is identical.
- 157: `unit <= 0.04045` → `<` — `unit = value / 255` for an integer byte never equals 0.04045 (0.04045 × 255 = 10.31…).
- 247: `i < 4` → `i <= 4` — a fifth pass reads capture groups past the end of the match (`undefined`) and writes nothing.
- 289: `text.length === 11 &&` → `true &&` — length pre-check that skips `toLowerCase()`; only 'transparent' (11 chars) matches anyway.
- 490: `{ r: 0, g: 0, b: 0 }` → `{}` — `hslValuesToRgb` writes r, g, b in that order; the literal only fixes the object shape (hidden class) for speed.
- 508: `hue >= 0 && hue < 360 ? hue : modulo(...)` → `false ? …` — skips the slow `%` for in-range hues; `modulo` returns the same hue.
- 508: `hue >= 0` → `hue > 0` — hue 0 goes through `modulo(0, 360)`, which is 0.
- 508: `hue < 360` → `hue <= 360` — h = 360 gives k = offset + 12, reduced by the `k >= 12` step to the same k as h = 0.
- 530: `k >= 12` → `k > 12` — k = 12 and k = 0 give the same channel (`max(-1, min(k - 3, 9 - k, 1))` is -1 for both).
- 711: `ratio >= threshold` → `>` — an exhaustive search over all 2^24 luminances found no colour pair whose ratio is exactly 3, 4.5 or 7, so equality never happens.
- 651, 652: `start < end` → `true` / `<=`, `end > start` → `true` / `>=` (`trimmed`) — the two trim loops can only meet inside a run of spaces; once `start` reaches `end` the other loop's character test fails on the same spaces (or on the end of the string, where `charCodeAt` is `NaN`), so the bounds check only stops a loop one step earlier.
- 666: `text.length === 11` → `true` — a fast path: `toLowerCase` cannot turn a string of another length into `'transparent'` (no character outside ASCII lower-cases to one of its letters).
- 766: `NAMED_COLORS === undefined` → `true` — decodes the named-colour table on every call instead of once; same table.
- 798: `text.length > 20` → `false` (`parseNamedColor`) — the longest colour name has 20 letters, so a longer string is not in the table and the lookup returns `undefined` anyway.
- 851: `let best = ''` → `"Stryker was here!"` (`toColorName` with `nearest`) — the table is never empty, so the first entry always replaces the initial value (its distance is below `Infinity`).
- 1090: `hue >= 0 && hue < 360` → `true` / `false`, `>=` → `>`, `<` → `<=` (`rgbToHsv`/`hsvToRgb` hue normalization) — the condition is a fast path around `modulo(hue, 360)`, which returns the same value for a hue already in `[0, 360)`; at exactly `0` and `360` both branches give `0`.
- 1110: `k >= 6` → `k > 6` (`hsvChannel`) — k = 6 and k = 0 give the same channel (`max(0, min(k, 4 - k, 1))` is 0 for both).
- 1333, 1334, 1340: `t <= start` → `<`, `t >= end` → `>`, `positions[middle] <= t` → `<` (`colorScale`) — at a stop position the other branch mixes with a weight of exactly 0 or 1, and `mix` returns that stop unchanged in every space and hue mode (checked on 480,000 random pairs).
- 371, 2002, 2180: `[0, 0, 0]` / `[0, 0, 0, 0, 0, 0]` → `[]` (`oklabOf`, `toLab`, `deltaE`) — `oklabInto` and `cielabInto` write every index in order, so the result is the same array; the literal only gives it a packed shape.
- 394: `Math.hypot(…) < ACHROMATIC` → `<=` (`oklabInto`) — equality never happens: every 8-bit grey lands near `1e-16`, every other 8-bit colour above `1e-3`.
- 1960: `value > 216 / 24389` → `>=` (`labCompand`) — both branches give `6/29` at `ε`, and an exhaustive search over all 2^24 colours found no X, Y or Z exactly equal to `ε`.
- 2417: `darkest >= lightest` → `>` (`colorFromString`) — a tie needs a background luminance with `(L + 0.05)² = 0.0525`; an exhaustive search over all 2^24 colours found none (closest gap `2.4e-7`).
- 2418: `Math.abs(passes - fails) > 0.0005` → `>=` (`colorFromString`) — the bracket only equals `0.0005` exactly for a lightness of the form `0.0005 × 2^k` (`0.512`), and the extra halving then moves the result by at most `0.00025` of lightness, within its 8-bit level: no difference over 10,000 searched string and background pairs.
- 411, 412: every mutant of the two fast paths of `isInsideChannel` (`if (…) return true` / `return false` → `false`, `>` → `>=`, `<` → `<=`, `-0.0000058` → `+0.0000058`, `||` → `&&`, either side → `false`) — they only decide without `Math.pow` for channels away from the gamut bounds; any channel they no longer decide falls through to the exact test on the encoded value, which gives the same answer (checked against the previous implementation, including right at the boundary).
- 441: `value <= 0` → `< 0` (`clipChannel`) — at `0` (or `-0`) the general path gives `fromLinear(0) = 0` and `toLinear(0) = 0` too.
- 442: `value > 1.0000001` → `false` / `>=` (`clipChannel`) — above `1.0000000000000004` the general path gives `Math.min(fromLinear(value), 1) = 1` and `toLinear(1) = 1` too.
- 452, 1774: `[0.5, …]` / `[0, 0, 0]` → `[]` (`GAMUT_SCRATCH`, `inGamut`) — every index is written before it is read; the literals only give the arrays a packed double shape.
- 495: `l > 0` → `true` / `>=` (`oklchToBytes`) — at `l <= 0` the mapping cannot get within one JND of the unclipped colour (its lightness is out of reach), so the chroma search runs down to below `0.0001` and the result is black, as with the shortcut (no difference over 700,000 random and near-boundary inputs).
- 496, 1773: `c > 0` → `c >= 0` (`oklchToBytes`, `inGamut`) — only `c = ±0` changes branch, and `Math.min(±0, MAX_CHROMA)` is a zero too: the same channels.
- 503: `isInside(rgb, 3)` → `false` (`oklchToBytes`) — an in-gamut colour is then clipped instead: it moves by at most `GAMUT_EPSILON` per channel (far below one JND, so no search follows), which never changes an 8-bit channel.
- 507, 518: `>= 0.02` → `> 0.02`; 519: `0.02 - delta < 0.0001` → `<=`; 510: `max - min > 0.0001` → `>=` (`oklchToBytes`) — exact equality of these float distances never happens (no difference over 700,000 random and near-boundary inputs).
- 509, 521: `minInGamut = true` → `false`, `minInGamut = false` → `true`; 513: `minInGamut && isInside(rgb, 3)` → `false`, and its block emptied (`oklchToBytes`) — CSS Color 4's `min_inGamut` shortcut skips clipping while the lower bound is in gamut, where clipping is (nearly) the identity and the delta far below one JND, so the search takes the same steps and ends on the same clipped colour (no difference over 700,000 random and near-boundary inputs).
