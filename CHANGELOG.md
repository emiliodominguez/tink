# Changelog

## 1.4.0

About 75 new helpers, including a new `path` module, each with property tests against an independent reference (node-semver, `node:path`, `node:crypto`, `node:zlib`, the WHATWG event-stream algorithm and web-platform-tests, cronie's main loop, Sharma's CIEDE2000 data, published test vectors), 100% coverage and a mutation run, then a second, independent review that fixed what it found:

- **`path` (new module):** POSIX path helpers for every runtime, without `node:path`: `basename`, `dirname`, `extname`, `isAbsolutePath`, `normalizePath`, `joinPath`, `resolvePath`, `relativePath`, `parsePath`/`formatPath` and `toPosixPath`. Each returns byte for byte what Node's `path.posix` returns for every string input, quirks included (`dirname('//a')` is `'//'`, `basename('/dir/', 'xdir')` is `'dir/'`, `normalize` keeps a trailing slash), checked against `node:path` on random and exhaustive small inputs and on Node's own test vectors. `resolvePath` and `relativePath` resolve relative paths against a virtual root `/` instead of `process.cwd()`. Non-strings throw a `TypeError`, even where Node skips them, and `formatPath` ignores parts inherited from a polluted `Object.prototype`. Every function is linear: Node's normalization is quadratic (an 80k-segment adversarial path takes seconds in Node, milliseconds here), paths that need no change come back without copying, and normalizing is about 2–3× faster than Node.
- **`iterables`: stream readers.** `readLines`, `parseSSE`, `parseNdjson`, `streamToText`, `streamToBytes` and `streamToArray` read WHATWG `ReadableStream`s (through their reader, so also where streams aren't async iterable), Node streams, `fetch` bodies and any (async) iterable of `string`/`Uint8Array` chunks. UTF-8 is decoded incrementally (a character split across chunks comes out whole, malformed bytes give the same U+FFFD as decoding the whole stream) and a leading BOM is dropped once. An early exit or an error cancels the stream (or calls `return()`) and releases its lock, and a `signal` cancels it at once, even during a pending read. Lines end at LF, CRLF and lone CR, also when the CR and LF arrive in different chunks, in linear time even for one huge line split over thousands of chunks; `readLines` is about 1.3× faster than `node:readline`. `maxLineLength` (and `parseSSE`'s `maxDataLength`, the joined data of an event) throw a `RangeError` only after the lines, events or values before the long one were handed out, whatever the chunking. `parseSSE` follows the WHATWG HTML event stream interpretation exactly (BOM, comments, one leading space, `data` joined with `\n`, `id` persisting and ignored when it contains NUL, digits-only `retry` with `onRetry`, events without data not dispatched, an unfinished event at the end discarded), checked against the web-platform-tests cases and a literal implementation of the algorithm, and works directly on `fetch(...).body` for LLM streaming. `parseNdjson` skips blank lines and throws a `SyntaxError` with the 1-based line number. `streamToBytes` copies once into a buffer of the exact size, faster than `Response#arrayBuffer()`.
- **`iterables`: combinators.** `mergeAsync` (arrival order, at most one pending `next()` per source, the others closed on early exit or error, no unhandled rejections; 1.6× faster than a `Promise.race` merge), `bufferTime` (a window opens at the first item of each batch, `maxSize`, never an empty batch, its timer cleared on every exit), a lazy round-robin `interleave`, `pairwise` and a type-guarded `partition`. Importing any `iterables` helper no longer bundles a top-level typed-array lookup.
- **`async`:** `createCircuitBreaker(fn, options)` is a closed / open / half-open breaker with `failureThreshold`, `resetTimeout` (or `Infinity`), `halfOpenMaxCalls` trial calls (all must succeed to close), an `isFailure` filter, `onStateChange` and an injectable clock. It uses no timers (the switch to half-open happens lazily on the next call or `state` read), short-circuited calls reject with a `CircuitOpenError` carrying `retryAfter`, and each call belongs to the generation it started in, so a late success of a call made while closed never closes an open circuit and failures from before a `reset()` don't count; it costs about 35 ns over a direct call. `backoff({ delay, factor, maxDelay, jitter, retries, random })` is a re-iterable sequence of exponential delays with the AWS "Exponential Backoff And Jitter" `'full'`, `'equal'` and `'decorrelated'` jitters, clamped at every step so it never yields `NaN`, `Infinity`, a negative value or more than `maxDelay`. `fromEvent` turns an `EventTarget` or a Node-style emitter into a buffered async iterator (`bufferSize` with `'throw'`/`'drop-oldest'`/`'drop-newest'`, `filter`, `rejectOn`, `signal`), removing every listener on `return()`, failure or abort. `interval` is drift-free (tick n at start + n·ms on a monotonic clock): missed ticks are skipped rather than run in a burst, async callbacks never overlap, and there is at most one timer and none once stopped. `createStopwatch` (pause/resume, laps, never goes backwards) and `isAbortError`/`isTimeoutError`, which recognise the module's errors, `DOMException`s, Node errors, errors of other realms and errors rebuilt from JSON, and never throw. `waitForEvent` now shares its listener code with `fromEvent`, with exactly its 1.3 behaviour (checked against the 1.3 build on 38,000 hostile-emitter scenarios).
- **`errors`:** `defineError(name, { code, ...defaults })` creates typed error classes: the name is on the prototype, `code` and the fields are own enumerable properties (array and object defaults typed as written without `const`), `cause` is read only when it is an own property, `instanceof` and subclassing work, the constructors stay out of the stack, and `NotFound.is(value)` never throws and recognises copies of the class from other bundles, realms and versions through a `Symbol.for` brand. They round-trip through `serializeError`/`deserializeError`, whose new opt-in `classes` option rebuilds your classes by swapping the prototype of a built-in error, so no user constructor is ever called and hostile classes (throwing getters, proxy prototypes) cannot make it throw. `getErrorChain` lists an error and its causes (and with `aggregate: true` the `errors` of an `AggregateError`, depth-first), iterative, cycle-safe and capped at 1000 levels. `formatError` prints `Name: message`, the stack frames (V8, Firefox and Safari formats), `[i/n]` aggregated errors and indented `Caused by:` lines, prints each object once (`[Circular]`, `[Seen above]`, `[Truncated]`), never throws, and stops indenting 10 levels down (deeper lines are marked `[depth N]`), so the report is linear in the size of the chain.
- **`functions`:** Result helpers consistent with `attempt`: `ok`, `err`, `isOk`, `isErr` (a thrown `undefined` counts as a success, as `attempt` produces it), `mapResult` and `unwrap` (rethrows the original error, so `unwrap(attempt(f))` behaves like `f()`). Ramda's `when`/`unless` (type guards narrow `fn`'s input; 9× faster than remeda's `when`) and `cond` (first match wins, `undefined` when none, every argument and `this` passed through, each pair read once when created; 2.8× faster than lodash's).
- **`decorators`:** `@lazy` computes a getter once per instance and stores it as a non-enumerable, read-only own property, so later reads cost the same as a plain field (13× faster than a `WeakMap` getter); errors are not cached, `delete` resets it, and frozen instances, `super` reads, statics and private getters fall back to a `WeakMap`. `@measure` times sync and promise-returning methods with `performance.now()` and reports `{ name, duration, args, failed, error }` to `onMeasure`; it keeps results, rethrows errors, leaves other thenables alone, and ignores what `onMeasure` or `clock` throw.
- **`date`: cron schedules.** `parseCron` reads Vixie cron (cronie) expressions strictly: 5 fields, or 6 with seconds first; lists, ranges, steps, `JAN`–`DEC`/`SUN`–`SAT`, weekdays 0–7, `@yearly`…`@hourly`, the either-day rule when both day fields are restricted, and croner's `L`, `wL` and `w#k`. Out-of-range values, reversed ranges, bad steps, empty items and unsupported syntax (`W`, `?`, `L-n`, `@reboot`) throw a `RangeError` naming the field. `nextCronDate`, `previousCronDate`, `eachCronDate` and `isCronMatch` take the parsed handle or the string (in a bounded cache), in an IANA zone, a UTC offset or local time, and jump field by field instead of scanning minutes (about 5 µs a call in New York, 260× faster than a minute scan); impossible expressions (`0 0 30 2 *`) are detected when parsed. Daylight saving follows cronie: a fixed-time job whose time is skipped fires once at the end of the gap and only on the first occurrence of a repeated time, wildcard jobs fire whenever the wall clock matches, and jumps of 3 hours or more are clock resets (Samoa 2011). Checked against a simulation of cronie's main loop and an independent `Intl`-based oracle in 30 zones around every kind of transition.
- **`validate`: semver ranges.** `satisfiesSemver`, `compileSemverRange` (compile once, test many), `isSemverRange`, `maxSatisfyingSemver`/`minSatisfyingSemver` and `incrementSemver` give the answers of node-semver 7.8.5 without `loose`: `||`, X-ranges, hyphen ranges with partial ends, tilde, caret, the pre-release rule and `includePrerelease`, build metadata, `v`/`=` prefixes, node's white-space handling and its limits. Checked against node-semver's own fixtures and about 12 million random ranges and 2.6 million increments from two independent generators, with no difference. Parsing is linear (hand-written scanners instead of a chain of regular expressions) with no global cache: satisfying is about 2× faster than node-semver (20× when its cache misses), a compiled range tests 6× faster than `Range#test`, `maxSatisfyingSemver` is 7× faster. Deliberate differences: `incrementSemver` throws where node returns `null` and never produces a number above `Number.MAX_SAFE_INTEGER`, and numeric pre-release identifiers beyond 2^53 compare exactly.
- **`encoding`:** `hmacSha256`/`hmacSha256Hex` (RFC 2104, synchronous, streaming the message through the existing SHA-256 without copying it; RFC 4231 vectors and `node:crypto`; 5× faster than `createHmac` on short messages). `crc32(data, initial?)`, the zlib CRC-32, chainable (`crc32(b, crc32(a)) === crc32(a + b)`) and equal to `zlib.crc32`, with slicing-by-8 over tables built on first use. HS256 `signJwt`/`verifyJwt`, synchronous: `verifyJwt` requires `alg` to be exactly `'HS256'` before it looks at the signature (no `none`, no algorithm confusion), rejects `crit`, compares in constant time, is as strict about base64url as `decodeJwt`, parses the payload only after the signature checks out, and checks `exp`/`nbf`/`iat` with jose's boundaries (`clockTolerance`, `maxAge` in whole seconds, injectable `now`), `issuer`, `audience` and `subject`. Failures throw a `JwtVerificationError` with a `code`, whose message never quotes the token, its claims or the secret. `signJwt` cannot override `alg` or write `crit`, refuses payloads with a `toJSON` method (own or inherited), and reproduces the jwt.io example token byte for byte.
- **`cache`:** `createTrie`, a radix tree with `__proto__`-safe keys, at most two nodes per key, prefix queries that cost the prefix plus the output and stop at `limit`, `longestPrefixOf`, `delete` that prunes and re-merges, and labels that never keep a deleted key or a source text alive; listings are in code-unit order and reuse each node's sorted children until it changes. `createBloomFilter` sizes itself optimally from `expectedItems` and `falsePositiveRate`, hashes with two MurmurHash3 lanes and enhanced double hashing, never allocates in `add`/`has`, estimates its false-positive rate and size, and saves and restores its bits with `toBytes()`. `createBiMap` (one-to-one, with an `inverse` view), `createMultiMap` (lists or `unique` sets), `createDefaultMap` (Python's `defaultdict`; the factory receives `-0` as `0`, like `Map#getOrInsertComputed`) and `createRingBuffer` (fixed capacity, overwriting the oldest value and reporting it to `onEvict`; 5× faster than array `push`/`shift`). Each is checked against a naive model with random command sequences.
- **`search`:** `createSearchIndex`, an in-memory full-text index ranked with Okapi BM25 (Lucene's non-negative IDF): per-field statistics and boosts, prefix matching that counts the best expansion per query term, `combine: 'and' | 'or'`, `filter`, a deterministic order, and exact, atomic `add`/`replace`/`remove` (no tombstones that skew IDF), checked against a BM25 written from the formulas on random histories. On 10,000 documents a rare term takes about 8 µs and a common term's top 10 about 0.3 ms (lunr: 0.19 ms and 20 ms). `tokenize`, a Unicode word tokenizer: letters and digits of any script with their combining marks, format characters ignored inside words (UAX #29), lower-cased then normalized to NFC, optional accent folding, `minLength`, `stopWords` and an optional `Intl.Segmenter` for CJK and Thai.
- **`color`:** `deltaE(a, b, { method })` (deltaEOK by default, or CIEDE2000 and CIE76 in CIELAB D50 like CSS `lab()`), with `toLab` and `ciede2000` exported: all 34 pairs of Sharma, Wu & Dalal (2005) match to 4 decimals. `colorFromString(text, options)` gives a stable, well-spread colour for a string (avatars, tags), built in OKLCH and gamut-mapped to sRGB, and with `contrastWith` guarantees a WCAG `minContrast` by moving only its lightness. `simulateColorVisionDeficiency(color, type, severity)` uses the Machado, Oliveira & Fernandes (2009) matrices, which are only bundled with it. OKLCH gamut mapping no longer allocates: OKLCH conversions, `mix` in OKLCH and parsing `oklch()` are 20–30% faster, with identical results.
- **Fixed (`date`):** `addBusinessDays` and `diffInBusinessDays` counted a local calendar day that never happened as a business day (Samoa skipped Friday, December 30th, 2011): `addBusinessDays(Sat 31, -2)` is now Wed 28 (was Thu 29) and `diffInBusinessDays(Mon 2 Jan, Thu 29)` is 1 (was 2).
- **Tests:** `yarn test:tz <path>` runs only the given tests in the six time zones (the path used to be swallowed by a coverage flag); two timing-dependent tests are now deterministic.
- **Package size:** existing helpers cost about what they did. The exceptions grow with the features they gained: `deserializeError` (+0.15 kB, `classes`), `addBusinessDays`/`diffInBusinessDays` (+0.15–0.2 kB, the skipped-day fix) and the OKLCH colour helpers (+0.1 kB, the allocation-free gamut mapping); `waitForEvent` shrinks by 85 B. The runtime budget of `yarn check:size` is now 154 kB gzipped for all 23 modules (was 124 kB) and the packed budget 600 kB (was 500 kB); the declaration check (`yarn check:types`) allows 80,000 type instantiations (was 66,000) for the new public types.

## 1.3.0

About 140 new helpers, each with property tests and 100% coverage: about 90 that other libraries (lodash, es-toolkit, radash, remeda,
ramda, date-fns, culori, validator.js, ufo, the p-\* family, async-mutex, nanostores, fuse.js, type-fest, Kendo and Syncfusion data
utilities) offer and tink lacked, and 47 math helpers checked against independent references:

- **`errors` (new module):** `toError` turns anything thrown (strings, `null`, symbols, objects with throwing getters, revoked proxies) into an `Error` with the original as `cause`, passing errors of any realm through; `getErrorMessage` and `isErrorLike` never throw. `serializeError` gives a JSON-safe object (`name`, `message`, `stack`, `code`, `cause`, `AggregateError` `errors`, own properties), cycle-safe, never throwing, and at most 1000 levels deep so that deeply nested input cannot overflow the stack; `deserializeError` rebuilds only built-in error classes, chosen by name, never calls another constructor, is prototype-safe, and never copies a key the error inherits (`toString`, `valueOf`…), so hostile data cannot break `String(error)`. Name, message, stack and the cause chain survive a JSON round trip.
- **Types (`tinkit/utils` and the package root):** 33 type-fest style utilities written from scratch: `PartialDeep`, `RequiredDeep`, `WritableDeep` (through arrays, tuples, `Map` and `Set`), `Writable`, `SetOptional`, `SetRequired`, `SetNonNullable`, `Except`, `RequireAtLeastOne`, `RequireExactlyOne`, `RequireAllOrNone`, `MergeExclusive`, `DistributedOmit`/`DistributedPick` (discriminated unions stay intact), stackable `Tagged`/`UnwrapTagged`, `IsEqual`/`IsAny`/`IsNever`/`IsUnknown`, `Jsonify` (honours `toJSON`, `Date` → `string`, drops `undefined`/function keys), `LiteralUnion`, `ValueOf`, `KeysOfUnion`, `NonEmptyArray` (what `isNonEmptyArray` narrows to), `Promisable`, `Arrayable`, `UnknownRecord`, `EmptyObject`, `IterableElement`, `AsyncReturnType`, `ConditionalKeys`, `ConditionalPick`. They are now listed in the API reference.

Also `upsert`, `filterMap` (drops `null` and `undefined`), `duplicates`, `associate` (null-prototype object from `[key, value]` pairs), `paginate` (1-based, with `pageCount`/`hasNext`/`hasPrevious`) and `splitAt`.

- **`functions`: F#-style pattern matching.** `matchWith(value).with(pattern, handler).with(pattern, when, handler).exhaustive()` (or `.otherwise(handler)`), over the patterns of `isMatching` (partial objects of own properties, exact-length tuples, guards, dates by time, SameValueZero): the first matching case wins, `when` guards never count toward exhaustiveness, handlers are narrowed to their pattern, and `exhaustive()` is a compile error naming the unhandled cases (`NonExhaustiveError<{ type: 'scroll' }>`) until unions, `boolean`, `null`/`undefined`, nested discriminants and tuples (`[true, _]` + `[false, _]`) are covered; at runtime it throws an `AssertionError` showing only the value's type. Exhaustiveness errs on the safe side: `any` input is only exhausted by a final `_`, and object types that arrays, strings or functions also satisfy, non-literal patterns (`` `id-${string}` ``) and `object`/`{}` patterns remove nothing; it assumes plain data (a class getter is not an own property: match classes with `isInstanceOf`). `matcher<T>()` is F#'s `function`: the same chain, compiled once, returning `(value: T) => result`. Helpers: `_` (wildcard, also matches a missing key), `capture`/`captureAs` (selections passed to the handler before the value, like F# `as`), `active` (active patterns: a function returning `undefined` for no match, called once per test, its result captured; a compile error unless it accepts every value at its position), `anyOf` (or-patterns whose alternatives capture the same names) and `cons` (`head :: tail`). One-shot matches interpret patterns without compiling them and stop at the first match. `match` is unchanged (551 B); `matchWith` alone costs about 1.8 kB.
- **`async`:** `createSemaphore` (fair FIFO permits, optional weights that can't be overtaken, per-request `signal`/`timeout` that leave the queue without leaking permits, listeners or timers, idempotent releases, `run(fn)`), `createMutex` (async-mutex's `runExclusive` is `run`), `createKeyedMutex` (per-key locks whose state is dropped when idle), `waitForEvent` (DOM `EventTarget`s and Node-style emitters, including `createEmitter`; `filter`, `rejectOn`, `timeout`, `signal`; removes every listener however it settles), `reduceAsync` (sequential, over sync or async iterables, abortable) and `minDelay` (p-min-delay, against loading-indicator flicker).

- **`guards`:** `isNode`, `isDeno`, `isBun`, `isBrowser` (functions, never throwing, and mutually exclusive: jsdom counts as Node and a bundler's `process` shim doesn't) and `isWebWorker` (any `WorkerGlobalScope`, so it is also true in Deno's workers, alongside `isDeno`), `getType` (a precise lowercase `TypeName` from brand checks, so `Symbol.toStringTag` can't fool it), `isAsyncFunction`, `isGeneratorFunction`, `isPropertyKey`, `isArrayLike` and a brand-checked `isBlob`.

- **`search`:** `ignoreDiacritics` for `fuzzyMatch`/`fuzzySearch` (default `false`): `cafe` matches `Café`, `strasse` matches `Straße`, and highlight ranges still index the original string exactly; a character whose folding would be longer than 3 letters (such as `ﷺ`) is kept as is, so folding at most triples the text being matched.
- **`math`:** `allocate` splits an integer or bigint amount (cents) by the largest-remainder method in exact arithmetic: shares add up to the total and each is within 1 of its quota. `wrap` (Euclidean, into `[min, max)`), `extent`, `covariance`, `correlation`, `linearRegression` (`slope`, `intercept`, `r2`, `predict`; accurate far from zero, e.g. on timestamps), `interquartileRange` and `zScore`.

  BigInt arithmetic) on 10⁵–10⁶ random inputs:

- **Fixed (`math`):** `variance` and `standardDeviation` now use the corrected two-pass algorithm instead of Welford's, which lost digits on
  data far from zero (`variance([1e15 + 1, 1e15 + 2, 1e15 + 4, 1e15 + 8])` was `7.1171875`, it is exactly `7.1875`); they still overflow only
  when the variance itself is beyond the doubles. `inverseLerp` (and so `mapRange`) keeps the sign of an infinite result when the range is a
  few subnormals wide.
- **Changed (`math`, `date`):** `clamp` and `clampDate` no longer throw when the bounds cross (`minimum > maximum`): the minimum wins, as in CSS `clamp(MIN, VAL, MAX)` and lodash, since layout code routinely computes bounds like `[0, containerWidth - panelWidth]` that cross before the first layout. A `NaN` bound still throws a `RangeError`.
- **Package size:** existing helpers cost what they did; the runtime budget of `yarn check:size` is now 124 kB gzipped for all 22 modules (was 92 kB) and the packed budget 500 kB (was 350 kB); the declaration check (`yarn check:types`) allows 66,000 type instantiations (was 60,000) for the new public types.

## 1.2.0

New helpers, each reviewed adversarially against its spec or reference implementation:

- **`encoding` (new module):** strict base64/base64url (`toBase64`, `fromBase64`, accepting exactly what `isBase64` accepts), hex (`toHex`, `fromHex`), WHATWG-exact UTF-8 (`encodeUtf8`, `decodeUtf8` with `fatal` and `stripBom`) and a synchronous `sha256`/`sha256Hex`, without `Buffer`; native `toBase64`/`fromBase64`/`toHex`/`fromHex`/`TextEncoder`/`TextDecoder` are used where they give identical results.
- **`async`:** `createBatcher`, DataLoader-style batching of every `load(key)` made until the microtask queue drains (after any number of `await`s): deduplicated keys, `maxBatchSize`, `delay`, per-key `Error`s, a clear `TypeError` for malformed results, per-call `signal`s with one abort listener per signal, and no cache by default (DataLoader's unbounded default leaks and goes stale); pass `cache: true` per request or an LRU, with single-flight requests, uncached errors and `clear` / `clearAll` / `prime`.
- **`validate`:** `parseEnv(schema, env?)` reports every missing or invalid environment variable at once, one per line, and no part of a value can reach the error, by construction: fixed messages and paths, other libraries' and custom messages become `Invalid value`, and a schema that throws is reported by its error name. Blank values count as unset by default, `prefix` maps `PORT` to `APP_PORT` / `VITE_PORT`, `strict` reports undeclared prefixed variables, and the output has a `null` prototype.
- **`url`:** typed route patterns: `matchPath` and `compilePath` (`/users/:id/:tab?`, `/@:handle`, `/files/*path`, optional segments), with parameters inferred from the pattern. Matching is linear in the pathname without a regular expression, decodes segments safely, rejects dot segments and traversal through encoded separators, and folds ASCII case only; building encodes values and guarantees the path matches back to the same parameters.
- **`objects`:** `replaceEqualDeep` (structural sharing like TanStack Query, linear on shared subtrees, safe on cycles) and JSON Patch (RFC 6902/6901): `createPatch`, an immutable, all-or-nothing `applyPatch` with structural sharing and prototype-safe pointers, `JsonPatchOperation` and `JsonPatchError`.
- **`date`:** IANA time zones without a bundled database: `isValidTimeZone` (narrowing to `TimeZone`), `getTimeZoneOffset`, `getZonedParts`, `fromZonedTime` (Temporal's disambiguation, and an exact round trip through `offset`), `formatInTimeZone` (the `formatDate` tokens plus `Z`/`ZZ`), `startOfDayInTimeZone` and `endOfDayInTimeZone`; they accept IANA names or `±HH:MM` offsets, never depend on the runtime's zone, and match Temporal on every transition of every zone from 1800 to 2100. `getCalendarMonth(year, monthIndex, { weekStartsOn, fixedWeeks })` gives date-picker grids.
- **`random`:** `uuidv7`/`createUuidv7` (RFC 9562, strictly increasing), `ulid`/`createUlid` (monotonic, throwing on overflow as the spec requires), and `uuidv7Timestamp`/`ulidTimestamp`; the clock and random source can be injected, and the defaults always use the CSPRNG.
- **`strings`:** `compareNatural` (a deterministic natural-order comparator: digit runs of any length, a total order, optional `ignoreCase`), `truncateMiddle` (grapheme-aware, with a `position`) and `stringWidth` (terminal columns: Unicode 17 East Asian Width, emoji sequences, ANSI escapes stripped; matches `string-width` on every assigned code point).
- **`math`:** `sumPrecise` (TC39 `Math.sumPrecise` semantics: exactly rounded and overflow-safe), `movingAverage` (exact running sums: no drift), `toSignificant` (significant figures, rounded as written) and `histogram` (d3-style bins with exact counts and correctly rounded edges).
- **`store`:** `createMachine`, a tiny typed state machine (states, context and event payloads inferred from the config; guards, context updates, `can`/`matches`, queued events from listeners, `useSyncExternalStore` snapshots), and `createHistory`, undo/redo for any store (`batch`, `coalesce` with an injectable clock, `limit`; a `createStore` change and its listeners' reactions are one step).
- **`color`:** OKLab/OKLCH: `toOklab`, `toOklch`, `oklabToRgb`, `oklchToRgb` (CSS Color 4 gamut mapping), `inGamut`, `toCssOklch`; `parseColor` reads `oklab()`/`oklch()` (as Tailwind v4's palette is written), `mix` takes `{ space: 'oklab' | 'oklch', hue }` like CSS `color-mix`, and `lighten`/`darken` take `{ space: 'oklch' }`. Defaults are unchanged; the string-parsing helpers grow by about 1.1 kB for the new syntax.
- **Fixed (`date`):** the day boundaries (`startOfDay`, `endOfDay`, `startOfMonth`…) of a day whose midnight fell in a DST gap that began the evening before (Toronto 1919), `endOfDay` when a day comes back hours after midnight (Alaska 1867), and `intervalToDuration`/`diffInMonths` across a skipped calendar day (Samoa 2011). Cached `Intl` formatters can no longer be corrupted by a polluted `Object.prototype`.
- **Fixed (`math`):** `average([MAX_VALUE, MAX_VALUE, MAX_VALUE])` returned `Infinity`.
- **Security (`url`):** `isSafeUrl`/`sanitizeUrl` and `buildQueryString`/`withQuery` read their options as own properties only: a polluted `Object.prototype.protocols` could make `isSafeUrl` accept `javascript:` URLs. The options of every `objects`, `strings`, `math` and `color` helper (`deepMergeWith`, `isMatch`, `flattenObject`, `sortKeys`, `mask`, `wordWrap`, `countSubString`, `variance`, `mix`, `toHex`, `getReadableTextColor`…), and of `isBase64`, ignore values inherited from `Object.prototype` (options from class getters or proxies still work).
- **Fixed (`url`):** `parseFormData` throws its own `TypeError` for an entry that is not iterable.
- **Types:** byte-returning helpers (`fromBase64`, `encodeUtf8`, `sha256`, `randomBytes`…) return `Uint8Array<ArrayBuffer>`, so their results pass to `crypto.subtle` and `Blob`; checking the declarations (`skipLibCheck: false`) now needs TypeScript 5.7+.
- **Tests** run in six time zones (Apia and Havana added, for skipped days and midnights); the size budget is 92 kB gzipped runtime and 350 kB packed.

## 1.1.0

Zod-like schemas, without the dependency:

- **`validate`: `parse` / `safeParse`** take a plain object of guards and parsers, return a typed output with unknown keys stripped, and report every issue with its path (`ValidationError`). Object schemas compile to specialized code on first use (falling back to a loop where `new Function` is blocked, e.g. by a CSP), and the bundled benchmarks parse nested records 1.6× faster than zod 4.
- **Strict coercion:** `asNumber`, `asInteger`, `asBoolean` and `asDate` reject what `z.coerce` silently converts (`''` → `0`, `'false'` → `true`, `null` → `0`, `'2023-02-29'` → March 1st, unsafe integers).
- **Combinators:** `withDefault`, `optional`, `nullable`, `transform`, `chain` (zod's `.pipe()`), `arrayOf`, `tuple`, `recordOf` (with an optional key guard), `union`, `discriminatedUnion` (direct variant lookup, tag first in the output; 1.25× faster than zod on the bundled event benchmark), cycle-safe `lazy` (recursive unions stay linear in the size of the value, and a value too deep to parse fails with an issue instead of a `RangeError`), `exact` (reject unknown keys), `partial`, `check` (zod's `.refine()`, with a message and a path for rules across fields), `withFallback` (zod's `.catch()`), `withError` (one message of your own in place of a schema's issues, for form fields), and `toParser` to hand any schema to a Standard Schema consumer. Every parser is a Standard Schema validator, and Standard Schema validators (zod, valibot, ArkType…) can be nested in a schema.
- **Real-world input:** `asArray` (a repeated query parameter is a string or an array), `asList` (a comma-separated list in an environment variable), `asBigInt` (64-bit ids beyond `Number.MAX_SAFE_INTEGER`), `blankAsUndefined` (an empty form field counts as missing) and `asJson` (JSON in an environment variable, pollution-safe); `issuesByPath` (`guards`) turns issues into per-field messages.
- **`url`: `parseFormData`** reads `FormData` (or `URLSearchParams`, or any `[key, value]` pairs) like `parseQueryString` reads a query string: a repeated field, such as a group of checkboxes, is an array instead of its last value.
- **`guards`:** `isDiscriminatedUnion` (direct variant lookup, with the tag added to each variant's type), `isIntegerInRange`, `isStringOfLength` and `isStringMatching` (stateless with `g`/`y` regexes). Their failures are explained without echoing the rejected strings.
- **Fixed:** `isArrayOf` and `isTuple` read the holes of a sparse array through a polluted `Array.prototype` or `Object.prototype`; holes are now always checked as `undefined`.
- **Faster:** `isShape` (and the object patterns of `isMatching`) compile to specialized code like `parse`, about 3.5× faster (2.9× faster than zod 4 on the bundled benchmark); `isUrl` recognises plain `http(s)` URLs without the URL parser, about 5× faster (2.4× faster than zod's `z.url()`), with every other URL going through the full check as before.
- **Fixed:** a recursive `isUnion` (through `isLazy`) whose members are told apart deep inside a value took time exponential in its depth, to check and to explain: each lazy guard now checks an object once per check, and `explain` reports the closest member only (a nested `isUnion` now scores as its closest member). A value nested too deeply to check is rejected (`Value is nested too deeply`) instead of throwing a `RangeError`.
- **Hardening (three review passes over every module, each fix with a regression test):**
    - **No hangs:** `countSubString` with a non-string needle, binary searches past 2^31 items, `parseJson` under a polluted `Object.prototype`, path readers on a `Proxy` that is its own prototype, and `mapConcurrent` on hand-written sources all terminate now.
    - **No blow-ups:** `isEqual`, `isMatch` and `diff` handle subtrees shared by many paths once (they were exponential); reporting an invalid deep `lazy` value and trimming non-Latin text are linear (they were quadratic); huge sparse arrays are walked by their elements.
    - **Hostile signals:** `async`, `emitter` and `iterables` helpers settle and clean up when an `AbortSignal`-like object's methods or `reason` getter throw, instead of crashing from a timer.
    - **Prototype pollution and frozen prototypes:** lookup tables, `Intl` options and parsed objects never read inherited values; `safeParse`, `setPath` and `unflattenObject` work under a frozen `Object.prototype`; `secureRandom` never serves bytes from a failed refill.
    - **Numbers and dates:** `roundToStep` is exact from 2^52, `averageBy([1e308, 1e308])` and `standardDeviation([-1e308, 1e308])` stay finite, springs settle at extreme ratios, and end-of-day/week helpers handle skipped and repeated midnights (Samoa, St. John's, Havana, Lord Howe).
    - **Clones:** `deepClone` keeps errors as real errors, resizable buffers resizable, and views that reach the end of one length-tracking.
    - **Types:** `pipe`/`compose` reject mismatched steps at compile time, `emitter` wrappers generic over the event map compile again, `retry` takes `PromiseLike`, and standard decorators accept methods that declare `this`.
- **Stricter inputs (may surface bugs in callers):** a few helpers now throw a `TypeError` instead of coercing nonsense: `clamp` with non-number bounds, `levenshtein`, `similarity`, `removeDiacritics`, `isPalindrome` and `countSubString` with non-strings, `mask`/`truncate`/`wordWrap` with non-string options, a `memoize` cache missing its methods, `mapKeys` returning a non-key, `typedFromEntries` and `parseFormData` given entries that are not pairs, and `createLRUCache` with a clock that does not return a number.
- **Package size:** the runtime budget of `yarn check:size` is now 72 kB gzipped (was 64 kB) for the new validation layer, and the packed budget 300 kB (was 280 kB) for the documentation the type declarations and `llms-full.txt` carry; per-helper import costs are listed in [docs/SIZES.md](./docs/SIZES.md).

## 1.0.0

Initial release of **tinkit** (`npm install tinkit`): strictly typed, zero-dependency, tree-shakeable utilities, published as ESM for Node 20.19+ and modern browsers.

### Modules

- **Data:** `arrays` (ordering, grouping, set algebra, combinatorics, Myers diff), `objects` (clone, merge, defaults, equality, immutable path updates, key-case transforms, stable hashing), `iterables` (lazy sync and async pipelines).
- **Validation:** `guards` (type predicates that compose into path-aware, [Standard Schema](https://standardschema.dev) validators), `validate` (linear-time string validators and a safe `parseJson`).
- **Text and URLs:** `strings` (grapheme-aware case, padding, trimming, truncation, escaping), `url` (query strings, safe URL editing and sanitising), `search` (fuzzy matching with highlight ranges).
- **Numbers, time and colour:** `math`, `date` (DST-safe arithmetic, durations, strict parsing), `format` (cached `Intl` formatting), `color` (CSS parsing, mixing, WCAG contrast), `easing` (CSS-accurate curves, springs).
- **Control flow and state:** `functions` (debounce, throttle, memoize, exhaustive `match`), `async` (retry, queues, rate limiting, single-flight memoization, cancellable concurrency), `cache` (LRU with TTL, priority queue), `emitter`, `store`, `random` (seeded and cryptographic), `decorators`.

### Guarantees

- **Hostile input:** path, merge, clone and query-string helpers never read or write through `__proto__`, `constructor` or `Object.prototype`; every regular expression runs in linear time; validators reject look-alike hosts and invisible characters; helpers whose cost grows with input size document it ([SECURITY.md](./SECURITY.md)).
- **Edge cases:** compensated sums, decimal-correct rounding, total orderings (`NaN`, `null` and `undefined` sort last), grapheme-aware text, wall-clock date arithmetic across DST changes, async helpers that leak no timers, listeners or unhandled rejections.
- **Bundles:** one ESM file per module, no code runs at import time (`yarn check:treeshaking`), a median of 450 B per imported helper ([docs/SIZES.md](./docs/SIZES.md)).

### Quality gates

Run by the pre-push hook (`yarn validate`): lint, formatting, type checking, 3,600+ tests in four time zones with 100% statement and branch coverage, fast-check property tests, every JSDoc `@example` executed against the build, a smoke test of the built package, size and tree-shaking budgets, a type check of the published declarations, and export resolution checks. Mutation testing (`yarn test:mutation`) and property stress testing (`yarn test:stress`) run on demand.
